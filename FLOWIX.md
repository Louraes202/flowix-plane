# Flowix fork of Plane

Plane Community (AGPL-3.0) with the Flowix brand and a few Flowix features. Changes are kept small and in their own files where possible, so a new Plane tag can be rebased with few conflicts.

## Branches

- `flowix/base-vX.Y.Z`: the upstream tag `vX.Y.Z`, untouched.
- `flowix/branding`: the Flowix changes on top of the current base. PRs go from here into the base branch.
- `flowix/<feature>`: a feature branch off `flowix/branding`, merged back into it by PR.

## Features

| Feature                                      | Files                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared calendar with events (not work items) | Backend: Django app `apps/api/plane/flowix/` (model `CalendarEvent`, table `flowix_calendar_events`, its own migrations), registered in `plane/settings/common.py` (`INSTALLED_APPS`) and `plane/urls.py`. API: `GET/POST /api/workspaces/<slug>/calendar-events/?start=&end=`, `GET/PATCH/DELETE .../calendar-events/<id>/`; admins and members write, guests read. Frontend: page `apps/web/app/(all)/[workspaceSlug]/(projects)/calendar/`, route in `apps/web/app/routes/core.ts`, components `apps/web/core/components/flowix-calendar/`, service `apps/web/core/services/flowix-calendar.service.ts`, types `packages/types/src/flowix-calendar.ts`, sidebar item `calendar` in `packages/constants/src/workspace.ts` + `workspace/sidebar/{helper,sidebar-item}.tsx` |
| Images as project logos                      | `TLogoProps.in_use = "image"` with `image.url` (`packages/types/src/common.ts`); drawn by `packages/propel/src/emoji-icon-picker/logo.tsx` and `apps/space/components/common/project-logo.tsx`; picker tab via the `extraTabs` prop of `EmojiPicker`; upload in `apps/web/core/components/project/logo-image-upload.tsx`, used in `project/form.tsx` (project settings). The file goes to the project asset endpoint as `PROJECT_COVER`, which serves it from `/api/assets/v2/static/<id>/` without replacing the cover                                                                                                                                                                                                                                                     |
| Strings                                      | `flowix.*` and `sidebar.calendar` in `packages/i18n/src/locales/{en,pt-PT}/navigation.json`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

The backend image is needed because of `plane.flowix`: api, worker, beat-worker and migrator must all run `flowix-plane-backend`. Its migrations depend on the last `db` migration of the base version; after a rebase onto a new Plane tag, run `python manage.py makemigrations --check` to confirm nothing is missing.

Brand: ink `#01010d`, blue `#1a6eff`, white. The mark is always blue; the wordmark follows the text colour.

When rebasing, check new upstream keys: `pt-PT` must have the same keys as `en` (missing ones fall back to English). Search for new promotion with `git grep -n "plane.so\|Upgrade\|github.com/makeplane" apps`.

Deployment and the update process are documented in the `flowix-vps` repo, `vps-b/apps/flowix-plane/README.md`.
